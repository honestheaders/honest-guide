PHP version checker for CVE-2026-109618 and CVE-2026-109619

SHORT ANSWER

On 21 October 2026 php.net released PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 to fix two critical remote code execution bugs (CVSS v4.0 9.2). Paste your php -v output, a X-Powered-By header, or php -i lines below to see whether your version is at or above the fixed release for its branch. It runs only in your browser: nothing you paste is sent anywhere.

Check your own site by opening it

A web page cannot read another site's headers on its own, so this works as a bookmark you click while your site is open (on a computer):

  1. Drag this link to your bookmarks bar: Check PHP headers
  2. Open your own site and click the bookmark. It reads the headers your browser already received from that page and opens this checker with them.

The headers travel after the # in the address, which browsers do not send to any server. The bookmark sends nothing to Honest Tools.

What headers can and cannot tell you: they show a PHP version only while expose_php is on. Many sites hide it, and distribution packages may carry the fix under an older number. If no version shows, check on the server with php -v or ask your host.

Where to get the version

  • On the server: php -v. The web server can run a different PHP than the command line, so also check the version your site reports (for example a phpinfo() page you then delete).
  • From outside: curl -sI https://your-site.example shows X-Powered-By: PHP/… only while expose_php is on.
  • Settings: php -i | grep -E "memory_limit|post_max_size|upload_progress.enabled|fatal_error_backtraces"

If you cannot update today

php.net says only an update is a complete fix. These settings reduce some attack paths but "do not make an installation safe":

  • session.upload_progress.enabled=0 in php.ini, an FPM pool or server config (not ini_set() or .user.ini), then restart every worker.
  • PHP 8.5 only: fatal_error_backtraces=0, then restart every worker.
  • memory_limit=-1, set where applications cannot override it (for example php_admin_value), and a low post_max_size (8M without uploads, 32M with uploads).
  • Hiding errors with display_errors or @ does not help.

Who this is not for

  • Linux distribution packages (Debian, Ubuntu, Red Hat and others) often fix bugs without changing the upstream version number. If your version has a suffix like -1ubuntu or deb12, the number alone cannot tell you; check your distribution's security notice.
  • This tool does not scan a site, test for the bug, or tell you whether you were attacked. For a hosted site, ask your host which PHP build they run.
