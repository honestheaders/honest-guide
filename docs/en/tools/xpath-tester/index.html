XPath tester

HOW IT WORKS

Paste HTML (for example, copied with Copy outerHTML in Chrome DevTools) and type an XPath. You see how many nodes match and the text of each one. It runs only in your browser: the HTML is parsed with DOMParser, which does not run its scripts, and nothing is sent anywhere.

    XPath you will use most

    • //li: every li element in the page.
    • //ul[@id='news']/li: the li children of the list whose id is news.
    • //a/@href: the href value of every link (an attribute, not the element).
    • //table//tr[td]: table rows that have data cells, which skips a header row made of th.
    • (//li)[1]: the first li in the whole page. //li[1] is different: the first li inside each parent.
    • //h3[contains(., 'Price')]: h3 elements whose text contains "Price".
    • count(//li): a number instead of nodes.

    Testing on a live page instead

    In Chrome DevTools, open the Console and type $x("//li/a"). Chrome's documentation says $x(path) "returns an array of DOM elements that match the given XPath expression". To pick an element and get every similar one as a table, our free extension Honest Scraper does that on the page itself.

    Who this is not for

    • The HTML you paste is a snapshot. Content that a page adds later with JavaScript is only there if it was in the DOM when you copied it.
    • Browsers support XPath 1.0 through document.evaluate. XPath 2.0 and 3.1 functions such as matches() or lower-case() are not available here, and will not work in the browser either.

    Guides that use this tool

    • Copy a web page table into a spreadsheet with XPath and the Console, no scraper needed
    • Test an XPath in Chrome DevTools: $x(), Elements search and document.evaluate
