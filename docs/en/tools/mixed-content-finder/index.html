Mixed content finder

SHORT ANSWER

An HTTPS page that loads anything over http:// has mixed content. Browsers upgrade images, audio and video to HTTPS and block the rest (scripts, stylesheets, iframes, fonts, srcset images). Click the bookmark on your own page, or paste its HTML, to list every http:// address and see which ones get blocked. It runs only in your browser.

Check a page of your own site

  1. On a computer, drag this link to your bookmarks bar: Find mixed content
  2. Open a page of your site and click the bookmark. It lists the http:// addresses in that page's HTML and opens this tool with the list. The list travels after the #, which browsers do not send to any server.

What browsers do with each kind

In the pageWhat happens
<img src>, <audio>, <video>, their <source>Upgraded to https://. Breaks if that server has no HTTPS. Not upgraded (blocked) when the host is an IP address.
<script>, <link> (stylesheets), <iframe>, <object>, srcset and <picture> images, fontsBlocked
<a href="http://…" download>A mixed download. Browsers commonly block it and let the user keep or discard it.

How to fix it

  • Change each address to https:// after checking that it opens over HTTPS. For files on your own site, a path that starts with / works too.
  • For a site with many old addresses, the header Content-Security-Policy: upgrade-insecure-requests makes the browser request them over HTTPS. A file that is not available over HTTPS then fails; there is no fallback to HTTP.
  • That header does not upgrade links people click to other sites, and it does not replace HSTS. See HSTS max-age and preload: a safe rollout order.

Who this is not for

  • It reads the HTML only. Addresses inside CSS files (url(http://…)), and requests made later by scripts (fetch, XHR), are not listed. For those, open DevTools Console on your page: Chrome shows a warning for each mixed request.
  • It checks one page at a time and does not crawl a site.
