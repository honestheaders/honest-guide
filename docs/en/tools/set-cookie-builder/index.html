Set-Cookie builder and checker

HOW IT WORKS

Fill in the cookie and pick its attributes. You get the Set-Cookie line to copy, and a warning for each combination that browsers reject or that is easy to get wrong. It runs only in your browser.

Your header

    The rules this checks

    • SameSite=None needs Secure. MDN: "The Secure attribute must also be set when using this value."
    • Partitioned needs Secure.
    • A name starting with __Secure- needs Secure. A name starting with __Host- needs Secure, Path=/ and no Domain.
    • Without SameSite, Chrome treats the cookie as Lax.
    • If both Expires and Max-Age are set, Max-Age wins, so this tool only uses Max-Age.

    More on the three SameSite values: SameSite cookies explained. To see and edit the cookies a site has already set: How to view and edit cookies in Chrome.

    Who this is not for

    • This builds one header line. It does not check what your server or framework actually sends; look at the real response in DevTools for that.
    • It does not encode special characters in the value for you. Keep values to letters, numbers and -_., or encode them in your code.
